# CommonLib 6.7.1 VR fixes

This branch retains the v6.7.1 implementation and dependencies while
backporting the reviewed VR and shared SE/VR corrections through v8.3.0.
It is a selective backport, not an upstream history synchronization.

- Base: `70c1acd5261210982bd52f6d4468a082fe04d798` (v6.7.1).
- Reviewed endpoint: `abe9ca7b7318dbc04bccfcd59fc3fb670244c2d7`
  (v8.3.0).
- No project-version bump, release tag, CSX dependency update, game
  deployment or performance claim is part of this branch.

## Adaptations and compatibility

- The frame-state accessors keep upstream AE version dispatch because
  universal builds must select the correct layout. The upstream
  `GetInsideFrame()` fallback incorrectly used legacy AE's `0x54` for
  SE/VR. This backport uses `0x50` on SE/VR, `0x54` on legacy AE and
  `0x60` on AE 1.7.99+, with a regression test for all four routes.
- Builds with AE support use frame-state accessors in place of direct
  `frameCount`, `insideFrame`, `compiledShaderThisFrame`, `letterbox` and
  `useEarlyZ` members, as required by the upstream layout correction.
- Input tests use the existing 6.7.1 `RUNTIME_1_6_1179` constant name.
- Contact-manager work corrects its existing enum/field without adding
  the unrelated new contact-manager virtual interface. The invalid old
  enum names are not retained as misleading aliases.
- The safe bone accessor remains public; the raw pointer remains private
  because its element stride differs between flat and VR runtimes.
- The removed `kSunGlintRefractionPass` name is replaced by the accurate
  runtime-specific names for slot `0x18`; accumulator storage is unchanged.
- Havok provenance comments retain the upstream activeragdoll reference.
  Newly exposed unrelated Havok classes and engine bindings are omitted.

## Adversarial review corrections

The review of `3e9a155f99ca7df75a010b97444badb55b5fdfe7` found three
defects in the selected upstream changes and their backport integration:

1. **Weather byte interpretation.** Signed precipitation bytes and an
   unconditional `1 + value / 255` fade-in threshold made low-byte values
   unable to start precipitation and high-byte fade-out values end too
   early. For example, a stored fade-in of 64 became a threshold greater
   than 1, while a fade-out of 192 became negative. Restored the original
   unsigned weather fields, consistent with xEdit's
   [WTHR DATA definition](https://github.com/TES5Edit/TES5Edit/blob/dev-4.1.5/Core/wbDefinitionsTES5.pas#L12597)
   and the existing CSX weather consumers. Both predicates now share one
   helper, preserving upstream's strict transition comparisons without
   duplicating normalization. This also avoids unrelated signedness
   changes to glare, damage, transition speed and wind fields.
2. **Unsafe menu views.** Adding VR accessors left the flat runtime view
   usable in VR. RaceSexMenu's VR-only direct fields also still included
   the absent camera, shifting sliders from native offset `0xF8` to
   `0x150`. Its VR-only members now use the same definition as the VR
   view, with size `0x160`. Inventory3DManager embeds flat preview members
   only in the SE-only build; other builds expose the confirmed VR array
   through its accessor without inventing the unknown VR tail. Both
   classes use the existing guarded pointer-accessor macros, rejecting
   mismatched runtimes with null in release builds as well as debug.
3. **Missing Havok type dependencies.** The typed foot/hand driver smart
   pointers required concrete types absent from 6.7.1, breaking copy,
   reset and destruction instantiation. Retained the existing erased
   reference type for these two members and a referenced-object pointer
   for the unconfirmed mirrored-skeleton type. Corrected offsets, raw
   transform pointers and the available animation-binding type remain.

### Accessor source compatibility

`RaceSexMenu` and `Inventory3DManager` now return nullable pointers from
both `GetRuntimeData()` (SE/AE) and `GetVRRuntimeData()` (VR). Callers must
check the returned pointer and use `->` instead of `.`. Const overloads
have the same runtime checks. VR inventory callers must use the explicit
VR view; the obsolete direct flat preview members are unavailable there.
This deliberately rejects unsafe old assumptions at compilation or at
the accessor boundary. No CSX dependency pin is changed by this review.

The review keeps all 21 logical items, with the adaptations above. The
excluded graphics migrations, dependencies and SKSE initialization remain
unchanged. It does not establish live-engine layout or performance proof.
The maintained generator also restored the missing `RaceMenuSlider.h`
export in `RE/Skyrim.h` for the already backported slider type.

The D3D11 migration (`c12c64ade`), SDK bridge (`80bf62138`) and shader
accumulator consolidation (`38e6399e5`) are excluded. Renderer resources,
SKSE initialization, dependency versions and the separate legacy
`ShaderAccumulator.h` remain at the base implementation. The only change
to `BSShaderAccumulator.h` is its render-mode enum.

the missing umbrella-header export; the final run passed both hooks.

BSShaderAccumulator still differs only in its render-mode enum. Review
logs are retained in `build/commonlib-vr-fixes-port/review` under the CSX

size assertion; the corrected runtime-specific assertions passed in all
four final builds. No live-game or CSX consumer build was run.
